## 1. 目标与原则

近期目标是让完整 Krita 从启动画面进入原版主窗口，并保证全部静态库内嵌 qrc 资源进入最终应用。之后生成可用的完整 Xcode 工程，再建立 Release 构建，最后继续画布、Pencil、保存和资源导入验收。

执行时遵守以下原则：

- 不把当前问题缩小成单个 `sql.qrc`；评审已证明静态库中的 qrc 资源整体未进入最终可执行文件。
- 不使用 `-all_load`、全局 whole-archive 或等价的全量强制链接。两个不同的 `defaulttools.qrc` 当前生成同名初始化符号，全量加载会引入重复符号风险。
- 先建立可靠门禁，再修改产品代码。构建成功、资源包 CRC 正常都不能替代内嵌资源检查和真机启动验收。
- 先用 Debug 做最短的启动修复闭环；任何性能、体积和笔刷延迟结论只能来自 Release。
- 完整 Xcode 工程问题与运行时 qrc 问题分别处理和验收。
- 保留现有 Qt Widgets 前端，不借修复机会重做界面。
- 按用户要求不暂存、不提交 Git。每一阶段以原子补丁导出、日志和产物哈希作为恢复点。

## 3. 工作包 0：保护现有成果和证据

### 3.1 加固补丁导出

修改 `packaging/ios/export-krita-patch.py`：

1. 验证 `upstream/krita` 是 Git checkout，HEAD 等于固定基线。
2. 在内存中生成完整 diff，包含已跟踪修改和未跟踪新增文件。
3. 默认拒绝空补丁；只有显式参数才允许导出空内容。
4. 写入同目录临时文件；对临时文件执行内容、正向或反向 apply 检查。
5. 检查通过后才用原子替换更新正式补丁；写入前后都记录大小和 SHA256，任何失败都保留原正式文件。

验收用例至少覆盖：正常脏树、干净树、错误 HEAD、无法生成某个未跟踪文件 diff、写入中断模拟。干净树不得把现有补丁改成 0 字节。

### 3.2 固化真机证据

如果原始截图仍可取得，将其复制到 `docs/ios/evidence/2026-09-23/`，用相对路径更新问题记录，并记录 SHA256。若原始文件已不存在，文档明确标注“会话内曾收到、工作区无原件”，不伪造或用其他截图替代。

后续真机测试统一保存：应用版本、IPA SHA256、设备/系统版本、测试日期、截图或崩溃日志。每份证据必须能追溯到一个明确产物。

### 3.3 磁盘与恢复点

当前数据卷只剩约 31 GiB，且现有 Debug 构建约 14 GiB。此阶段只登记可清理或可迁移目录，不执行删除。开始新的独立 Release 构建前，先取得用户对具体清理目标的授权，并保留当前 `.app`、IPA、补丁和关键日志。

工作包 0 的产物：补丁导出脚本测试记录、当前补丁哈希、证据索引、磁盘使用快照。

## 4. 工作包 1：建立可信的应用与 IPA 门禁

### 4.1 应用检查器

修改 `verify-krita-app.py`：

- 用显式检查和 `SystemExit` 替换全部裸 `assert`，确保 `python3 -O` 和 `PYTHONOPTIMIZE=1` 下仍会失败。
- 保留 ARM64、iOS platform 2、系统动态依赖、plist、默认资源包 CRC、无 `.a`、无符号链接检查。
- 增加构建类型证据：记录 Debug/Release、是否存在 `_debug` Qt 链接输入、优化和 `NDEBUG` 状态；Debug 允许用于 bring-up，但输出必须明确标注。
- 增加静态 qrc 清单检查，至少报告“静态归档中定义的资源初始化集合”“最终可执行文件中的集合”和两者差集。
- 将关键资源的预期初始化名和一个哨兵路径写入受版本控制的清单，至少包括 SQL、工具资源、SVG 文本、选择工具、变换工具、text properties、quick widgets 和 kxmlgui。
- 对 `:/create_version_information.sql` 同时检查初始化符号和二进制内的资源路径/内容标记，避免只看一个符号就宣告成功。

若某个归档属于测试或未链接功能，必须在清单中显式排除并写原因，不能静默过滤。

### 4.2 IPA 检查器

生成 IPA 后重新打开它并检查：

- ZIP CRC、唯一的 `Payload/krita.app`、Info.plist 可解析、CFBundleExecutable 存在。
- IPA 中的 Info.plist、主可执行文件和关键资源与刚验证的 `.app` 一致。
- 记录 IPA 大小和 SHA256。
- 明确验证签名状态。当前交付预期为“未签名”，不能把“没有执行检查”写成“未签名已确认”。
- 任一检查失败时删除或隔离本轮不完整 IPA，不能留下看似可交付的同名文件。

### 4.3 门禁自测

对检查器做故障注入：删除关键文件、篡改 bundle、放入符号链接、用 `python3 -O` 运行、制造缺失 qrc、损坏 IPA。每种情况都必须非零退出，不打印 `PASS`。

工作包 1 完成后，`package-krita.sh` 只有在应用检查和 IPA 二次检查都通过时才打印交付路径。

## 5. 工作包 2：通用修复静态 qrc 资源

### 5.1 先冻结完整资源清单

以评审的符号差集为起点，重新枚举最终链接闭包内的 qrc。当前已确认的缺失集合包括：

- `sql`
- 两组不同内容但同名生成符号的 `defaulttools`
- `karbontools`、`pathshapes`、`svgtexttool`
- `selectiontools`、`toolcrop`、`tool_polygon`、`polyline`、`tool_transform`
- `textproperties`、`kisquickwidgets`、`kxmlgui`

实现前要核对每组 qrc 的拥有 target、生成的初始化符号、至少一个哨兵路径，以及它是否已由 Qt/QML 静态插件机制自动导入。清单变化必须使配置或验证失败，不能悄悄漏掉新增 qrc。

### 5.2 首选实现

首选在 iOS 静态构建中建立显式资源注册表，同时保留 qrc 在原所属库中：

1. 在每个含 qrc 的相关 target 旁登记“target、唯一资源初始化名、哨兵路径”。
2. CMake 根据登记生成一个资源初始化源文件，并把它直接加入 `krita` 可执行目标。
3. 该源文件通过显式资源初始化调用产生对 qrc 对象的未定义引用，从对应静态归档中精确拉入资源对象；在资源数据库初始化之前调用。
4. 两个 `defaulttools.qrc` 在 iOS 静态构建中使用不同的生成资源名，例如 basic tools 与 flake/default tool 各自唯一；资源内部路径保持不变。
5. 资源注册表与 target 链接清单来自同一份 CMake 元数据，避免维护两份会漂移的手写列表。

这一方案不需要全量加载静态库，不改变桌面共享库行为，也能在将来新增 qrc 时通过门禁发现遗漏。

### 5.3 备选方案及拒绝条件

- 将所有相关 `.qrc` 直接编入 `krita_QRCS`：可以作为小型验证，但正式实现必须解决两个 `defaulttools` 名称冲突，并避免在库和可执行文件中重复编译资源。
- 对每个归档使用 `-force_load`：仅在精确到单个资源对象仍无法实现时评估；若拉入无关对象或出现重复符号则拒绝。
- 全局 `-all_load`/whole-archive：不采用。
- 只给 `sql.qrc` 增加 `Q_INIT_RESOURCE(sql)`：只可用于验证根因，不能作为最终修复。

### 5.4 构建级验收

- 最终可执行文件包含注册表要求的全部初始化符号，差集为空。
- `create_version_information.sql` 及所有登记的哨兵资源能在最终产物中被确认。
- 两组 `defaulttools` 均存在且没有重复符号。
- 147 个 Krita 插件导入数量不减少，Qt/Krita QML 静态导入仍存在。
- macOS、非 iOS 平台不进入新增分支；CMake 配置仍能生成。

## 6. 工作包 3：Debug 重建和真机启动闭环

### 6.1 增量 Debug 构建

使用当前 `.build/krita-ios` 做一次增量 Debug 构建，目的是快速验证启动根因，不作性能判断。构建前记录原 IPA SHA256；构建后生成新的、带不同文件名或版本标记的未签名产物，避免与失败样本混淆。

自动验收必须依次通过：源码补丁保护、编译链接、194 个目标归档架构检查、应用检查、qrc 差集、IPA 二次检查。

### 6.2 真机验收 A：启动与资源

用户签名安装后，按以下顺序测试：

1. 首次启动不再出现 SQL 文件缺失。
2. 资源数据库可在 `Library/Application Support/krita/` 创建并打开。
3. 四个默认 bundle 同步完成，不再出现内存/数据库或 brush tip metadata 连锁错误。
4. 进入原版 Krita 主窗口，菜单、工具栏和 Docker 显示。
5. 退出并第二次启动，确认数据库复用而不是每次重建失败。

如果出现新的“资源找不到”，先与工作包 2 的完整清单比对，不逐个临时硬编码。若数据库恢复后仍有 bundle 同步错误，将它拆成独立问题，不再默认视为 SQL 的连锁结果。

本工作包完成门槛是“主窗口连续两次启动成功”，不是只看到启动图，也不是只消除首个弹窗。

## 7. 工作包 4：完整 Xcode 工程

### 7.1 隔离最小复现

用 Qt 6.10.3 iOS 静态 kit 和 Xcode 生成器制作最小 CMake 复现，保留与失败相同的 `Qt6::Gui` 和 `check_cxx_symbol_exists`/`try_compile` 条件。确认问题是否来自 Qt 导入目标中的 `$<TARGET_OBJECTS:Qt6::Gui_resources_1>` 被传播到检测工程。

### 7.2 首选修复方向

Krita 的相关检查只需要编译头文件、宏或成员声明，不需要链接完整 Qt Gui。首选对 iOS/Xcode 使用 compile-only 检测：

- 为检测传入必要 include directories 和 compile definitions。
- 避免把含静态资源对象生成表达式的 `Qt6::Gui` 链接接口导出到 `try_compile` 子工程。
- 必要时在受限作用域设置 `CMAKE_TRY_COMPILE_TARGET_TYPE=STATIC_LIBRARY`，检测后恢复。
- 不硬编码“补丁存在”结果，不用预设 cache 值掩盖检测失败。

### 7.3 验收

- `configure-krita-xcode.sh --fresh` 成功结束。
- 生成的工程包含完整 Krita target/scheme，而不是 CompilerId 工程。
- 使用 `CODE_SIGNING_ALLOWED=NO` 能构建 ARM64 device `.app`。
- Xcode 产物与 Ninja 产物通过同一应用、qrc 和 IPA 门禁。
- bundle ID 与 Team ID 仍由参数传入，工程文件不保存个人身份。

已验证完整工程位置为 `.build/krita-ios-xcode/krita.xcodeproj`，主 scheme 为 `krita`。

## 8. 工作包 5：Release 构建

### 8.1 空间和配置

在创建独立 Release 目录前检查磁盘。若空间不足，列出具体目录、大小、是否可再生和拟执行动作，由用户确认后再清理或迁移；不删除现有唯一证据或补丁。

将构建类型改为参数化，Debug 和 Release 使用独立目录与产物名。Release 配置不能再由脚本默认值悄悄退回 Debug。

### 8.2 Release 门禁

- CMake cache 为 Release（或明确选择的发布配置）。
- 编译命令有发布优化和 `NDEBUG`；最终链接不引用 Qt `_debug` 静态库。
- 重跑全部应用、qrc、IPA 检查。
- 真机重复工作包 3 的启动与资源验收。
- 记录应用/IPA 体积、首次与再次启动时间、峰值内存和基础画布响应；不与 Debug 数据混为一组。

Release 真机启动成功后，才将它作为后续绘画和性能测试基线。

## 9. 工作包 6：基本绘画、缩放和 Files

按依赖顺序验收，每一组失败时停在首个根因：

1. 新建 1024 × 1024、8 位 RGBA 文档，确认 GLES 画布显示。
2. 默认 Pixel Brush 连续绘制，验证坐标、压力和倾斜；分别记录压力和倾斜证据。
3. 手指平移/缩放不误画；iOS 不再用单指触摸唤起轮盘，改由 `UIPencilInteraction` 的 Pencil 笔杆双击/捏压入口触发。
4. 让画布输入法属性跟随文本工具状态；图层和其他 item view 的普通触摸不得隐式开始文本编辑，显式重命名与文本工具仍能正常输入。
5. 鼠标/触控板和外接键盘做基础检查。
6. 图层新增、撤销/重做、关闭与重开 `.kra`。
7. 将现有 Android 动态 UI 缩放泛化到 iPadOS，提供 100/125/150/175/200%，默认 150%；验证画布逻辑坐标、图像像素和笔刷位置不发生二次缩放。
8. 验证 Qt 原生文件对话框能否正确提供 Files 安全访问；只有确认不足时才增加最小 Objective-C++ 桥接。
9. 导入 `.kpp`、`.bundle`、`.abr`，重启后确认资源数据库持久化并可被对应内置引擎使用。

探针结果只作为输入行为参考，不替代完整 Krita 的任何一项验收。
Pencil 轮盘和输入法误唤起的具体源码位置与验证矩阵见 [Pencil 轮盘手势与输入法修复计划](input-gesture-and-keyboard-plan-2026-09-24.md)。

## 12. 完成定义

近期修复完成需要同时满足：

1. 校验链路无法被优化模式绕过，IPA 生成后会被实际复验。
2. 静态链接闭包中的要求 qrc 全部进入最终可执行文件，差集为空。
3. Debug 真机连续两次进入主窗口，资源数据库和默认资源同步成功。
4. 完整 Krita Xcode 工程能够生成并无签名构建。
5. Release 产物通过相同门禁和真机启动验证。

整个第一阶段目标完成还需要：Pencil 基础绘画及压力/倾斜、触控分离、图层撤销、`.kra` 保存重开、可配置 150% GUI 缩放、Files 文档操作，以及至少一种外部笔刷/资源包导入在完整应用中通过真机验证。
